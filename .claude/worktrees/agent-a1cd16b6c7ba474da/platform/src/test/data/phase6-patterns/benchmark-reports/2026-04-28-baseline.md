## Findings

1. **`activation_count_30d` is self-healing.** The `refreshActivationCounts`
   step at the start of `promotePatterns` recomputes from
   `causal_edges.created_at >= NOW() - 30d`, so dropped/expired edges
   automatically lower the count without manual upkeep. Tests demonstrate
   this works whether `matchEdgeToPattern` has run or not.

2. **Q5 SQL CAS (`UPDATE ... WHERE status=$prev RETURNING`) is sufficient
   for the realistic concurrency window.** The Promise.all test confirms
   that two parallel `promotePatterns` calls produce exactly one transition
   per pattern. No row locks needed.

3. **Q3 sync naming with try/catch is robust.** The mocked-failure test
   shows the row stays at `candidate` with `name=NULL` when Haiku errors,
   and the next promotePatterns call won't re-attempt naming for that row
   (idempotency check on `pattern.name` first). Operationally that means
   a name=NULL row is a tombstone — needs explicit re-trigger to retry.

4. **`fact_predicates.category` fallback is essential.** Predicates that
   aren't in the catalog land at `predicate_category = predicate` (the
   literal string). This keeps un-categorised chains clustering
   deterministically rather than collapsing every uncategorised chain
   into a single "unknown" bucket.

5. **Latent bug surfaced + fixed.** During test development we discovered
   that the snake-to-camel transformer in `src/db/raw.ts` doesn't handle
   `_<digit>` (regex matches only `_<lowercase letter>`). `activation_count_30d`
   was landing as `activationCount_30d` not `activationCount30d`. Fixed
   in-place via SELECT alias (`AS activations30d`) — see G3 commit notes.

6. **`CLEARABLE_TABLES` was missing audit-trail tables since migration 009.**
   `/api/viz/clear` and `/api/reset` had been silently 500'ing on
   FK-violation due to `fact_history` and `causal_edge_history` not being
   in the deletion order. Fixed atomically in commit 670971d before G1.

## Graduation criteria

Phase 6 promotes from L1+adversarial scaffolding to L3 corpus hardening
under `nmemo-klv.6` when:

1. The test-harden skill evolves the adversarial fixtures from scaffolds
   to populated content (50+ canonical patterns for ghost-flood, 100
   chains for pattern-poisoning).
2. `nameCandidatePatterns` quality is benchmarked — does Haiku produce
   meaningful names? Does it correctly flag pattern-poisoning corpus as
   semantically meaningless?
3. Real MISRA rule chains emerge from ingest + detection cycle without
   false positives under noise.
4. Ghost detection precision degrades gracefully under increasing noise
   levels (target: ≥80% precision at noise=0.3).
