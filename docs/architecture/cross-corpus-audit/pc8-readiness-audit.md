## Detail — the ones that matter

**PC8-1 (the dangerous one).** `applyPromotion` computes entity embeddings via a local `embed()` that catches any failure and returns `[]` (`promotion.ts:187-193`); the write is guarded `if (vec && vec.length > 0)` before `UPDATE public.entities SET embedding = …` (`promotion.ts:280`). When Ollama/ML 503s, the entity is minted and promotion reports success, but the entity has NO embedding — pgvector recall over it silently returns nothing. Same failure shape as the AGE/localtimestamp incident. It sits on the exact path Phase A extends (corpus_id on entities, corpus-scoped minting) and E1 recall depends on embeddings being present. No existing test catches it (PC8-6). Fix: make the embed failure loud (or emit a health metric + mark row for re-embed). CAVEAT: lives inside the epoch promote path the prior review "covered" — confirm it wasn't already logged there before filing a bead.

**PC8-2.** `clearGraphTables()` iterates a 17-entry `CLEARABLE_TABLES` constant; the DB has ~42 `public.*` tables. Omitted: the three staging tables, `arbiter_verdicts`, `edge_source_refs`, `fact_sources`, `fact_units`, all cluster/topology/drift state, `graph_stats`, `derived_freshness`, `cross_cluster_runs`, `stream_participants`, `capture_idempotency`, `llm_usage`, and AGE `knowledge_graph`. Live-DB confirms: 1067 AGE nodes vs 4 `public.entities` — orphan accumulation. When the feature clones the staging family it must extend this list; the allowlist-by-hand pattern will silently omit new tables unless reset is re-derived from a schema registry.

**PC8-3.** `create_llm_client()` (`llm.py:1004-1013`) treats everything except `"zai"`/`"pi"` as ClaudeCodeProvider with only an info log. `startup-validation.ts` resolves `LLM_PROVIDER ?? 'pi'` while `llm.py:1001` uses default `"claude"` — unset var → Node probes Pi health while Python builds Claude. Fix: validate against an allowed set, raise on unknown, align the two defaults.
