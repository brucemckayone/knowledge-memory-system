# v0.2 — Adaptive Surfaces & Interactive Content (built, then carved back)

**Status:** Implemented end-to-end during commits `4f68625`…`8fc0896` (April–May 2026), then carved back in v0.3. This document captures both: what was built (so the code is legible) and what stayed once the surface area was cut.

If you're looking for the *current* shape of the app, jump straight to "v0.3 — the cut" at the bottom.

---

## What was built

Six work-streams shipped in sequence:

| Phase | Theme | What landed |
|-------|-------|-------------|
| 1 | Background patrol layer | `patrol_runs`, `insights` tables, patrol cron, 4 new MCP tools, insights feed routes |
| 2 | Dashboard & discovery | `/api/dashboard` composite endpoint, daily quiz, daily flashcards, insights feed, cross-course connections, graph snapshot |
| 3 | Component framework | Preact + htm + signals, lazy mermaid, 8 components (Callout, Mermaid, SvgFigure, CodeRunner, StepThrough, FlashcardDeck, ConceptMap, Highlight), `LessonRenderer`, structured lesson document format |
| 4 | Dynamic component generation | `component-generator` agent, `generate_component` MCP tool, structured chat tutor responses, "Pin to lesson" affordance |
| 5 | Lesson evolution | `lesson_overlays` + `notes` schema, `edit_lesson_section` MCP tool, highlight popover with explainer agent, version history UI |
| 6 | Cross-course intelligence | Article generator agent, cross-course bridge UI, patrol surfaces `cross_course_link` insights |

All of it is in the repo. None of it has been removed.

## What was wrong with the result

The system grew six new tabs and a thicker UI before the core "learner reads a lesson, tutor sits next to them" flow had been validated. By v0.3 the navbar carried Dashboard, Courses, Learn, Quiz, My Gaps, Progress — the learner had to choose where to be before learning could begin, and the chat lived in its own destination disconnected from whatever they were reading.

The two structural problems:

1. **Chat as its own destination.** A standalone "Learn" tab where the chat had no idea what the learner was looking at. The chat couldn't lean on highlighted text, couldn't edit the lesson the learner was on, couldn't generate components into the lesson, couldn't be the always-on tutor next to the page.
2. **Surfaces without a journey.** Quiz, My Gaps, Progress lived as tabs because we built features that produced data and gave each one a tab. The learner has no reason to walk to a "Quiz" tab when questions live at the bottom of every section page.

## v0.3 — the cut

The shape kept after the carving:

### Two tabs

`Dashboard`, `Courses`. That is the whole top-level navigation.

- **Dashboard** is the home — surfaces what the patrol found, jump-back-in, daily quiz card, daily flashcards, cross-course connections, graph snapshot.
- **Courses** lists courses and is the path into a course → section → lesson.

The retired tabs and how their content is reachable now:

| Removed tab | Where its content lives now |
|-------------|------------------------------|
| Learn (chat) | Persistent chat sidebar on every section page |
| Quiz | Inline questions at the bottom of every section page |
| My Gaps | (Decision deferred — gap analyzer agent retained, surfaced from dashboard or removed piecewise) |
| Progress | (Decision deferred — stats can surface as a dashboard card or be removed) |

### Section view = lesson + persistent chat sidebar

```
┌── Lesson pane ────────────────────────┐ ┌── Chat (persistent) ──┐
│ ## Why this matters                   │ │ Tutor: this section…  │
│ A closure is a function...            │ │                       │
│   ┌─popover (existing) ─┐             │ │ You: walk me through  │
│   │ means: when a fn… │ │             │ │  the counter example  │
│   └────────────────────┘             │ │ Tutor: …              │
│                                       │ │ ┌─[StepThrough]────┐ │
│ ── Inline questions ──                │ │ │ Step 1 of 5 ▶    │ │
│ Q1. What does this print?             │ │ └────────[📌pin]──┘ │
└───────────────────────────────────────┘ └───────────────────────┘
```

**Layout decisions:**
- Default open, resizable + collapsible via `toggleSectionChat()`.
- Sidebar lives at the view level (not inside `#sectionContent`) so lesson re-renders don't tear the chat down.
- One chat thread per `(learner, section)`. Thread persists across visits; cross-course MCP context is always available.
- Highlight popover (the existing explainer agent) stays — quick lookups are popover, longer conversation is sidebar. They do not hand off to each other.

**Chat capabilities (all already built, all wired in v0.3):**
- Answer questions about highlighted text — handled by the existing explainer popover, not the sidebar.
- Generate components inline — `component-generator` agent invoked via the `generate_component` MCP tool.
- Edit/extend the lesson — `edit_lesson_section` MCP tool writes to the per-learner overlay.
- Pin generated content into the lesson — `/api/lesson-pin` route promotes a chat block into the overlay.

### Schema change

`chat_sessions` gains `section_id` (nullable). One session per `(learner, section)`; non-section surfaces can still create un-scoped sessions where it makes sense. `GET /api/chat/sections/:id/session` is idempotent — returns the existing thread or creates one.

The chat tutor agent now takes optional `sectionTitle` and `sectionExcerpt` so its response can be grounded in what the learner is actually reading. Cross-course memory still flows through MCP read tools (`get_learner_understanding`, `get_struggle_areas`, etc.), which the tutor calls before responding.

### What stays definitively

- Patrol cron + insights feed (powers the dashboard cards).
- Cross-course bridge link at top of section ("you've seen this before in [Course X]").
- Inline questions on the section page + answer evaluator (still writes to the graph via MCP).
- Component library + `LessonRenderer` (lessons render structured blocks; chat renders structured tutor responses).
- Lesson overlay edits + notes + highlight popover.

### What's deferred — decide piecewise

These all still exist in the repo, with no UI surface after the cut. Each gets a re-evaluation now that the new vantage is in place:

- Gap analyzer agent — does a "Find my gaps" button on the dashboard earn its place, or delete?
- Cross-course articles — keep on dashboard as synthesis cards, or delete?
- Flashcards — keep dashboard daily-review card, or delete the table + agent?
- Progress stats — keep as a dashboard card, or delete?

The principle when judging each: **does this lean on the graph in a way that brings the learner closer to a lesson?** If a feature only "produces something for a tab" the answer is delete.

## Order of work going forward

The structural cut is the foundation. Next decisions are content-level, not architectural:

1. Try the section-page-with-sidebar flow on a real course. Validate that the chat genuinely feels like a sidekick, not a chatbot.
2. Decide each deferred feature one by one based on whether its absence is felt.
3. Doc updates: re-read this file in three months and either re-promote a deferred feature or delete the dead code.

## Out of scope (still)

- Multi-learner. Single learner only.
- Auth or accounts.
- Mobile-specific UI.
- Course marketplace / sharing / exporting.
- Voice input/output.
- Grading or external assessment integrations.
