# 23.5 — Centrality (PageRank + Sampled Betweenness)

**Phase:** 2 (T0 topology primitives, ships last — most parameter-sensitive)
**Master:** `23-topology-primitives.md`
**Status:** Design draft (2026-04-29) — under review
**Bead:** to be created post-review

## 1. Purpose

**Question it answers:** Who are the protagonists? Who's the bridge?

Different centrality metrics answer different questions; we ship two:

- **PageRank** — structural importance with damping. Captures "this entity is important because it's connected to other important entities." Cheap to compute, well-behaved on disconnected graphs (the damping factor handles teleport).
- **Sampled betweenness** — bridge-ness. Approximates "how often does this entity sit on shortest paths between others?". Exact betweenness is O(n·m), too expensive at 10k+ entities; the Riondato-Kornaropoulos sampling approximation gives ε-tolerance bounds in O(k·m) for sample size k.

These two cover the most operationally useful centrality dimensions:
- The reasoning agent uses centrality to *boost* (not replace) its `last_reasoned_at` cooldown ranker, prioritising high-PageRank entities for investigation when cooldown is satisfied
- Phase 4's cross-cluster generator can rank candidate pairs by `min(pagerank_A, pagerank_B)` — bridging two important entities is more valuable than bridging two minor ones
- Viz dashboards surface "the protagonists of this corpus" with a sort by PageRank

Three other centralities (degree, closeness, eigenvector) are not implemented in Phase 2:
- **Degree** is trivially queryable: `SELECT entity_id, COUNT(*) FROM facts ... GROUP BY entity_id`. No need to materialise.
- **Closeness** is O(n·m) per source vertex — too expensive without sampling, and doesn't add much beyond PageRank for our use cases.
- **Eigenvector centrality** is closely related to PageRank without damping; PageRank is more robust on real-world graphs.

Future capability docs may add these if needed.

## 2. Design

### 2.1 PageRank

Standard power-iteration PageRank with damping factor α = 0.85 (the historical default; well-tuned for web-scale graphs and equally reasonable here). Convergence threshold 1e-6 on L1 norm.

The graph projection is the same undirected one used by components and k-core. Direction-aware PageRank could distinguish "facts pointing to" vs "facts pointing from" the entity, but symmetric PageRank is sufficient for "structural importance" framing. Implementation: `igraph.Graph.pagerank()`.

Output is normalised so the column sums to 1.0 across all entities. This makes "top 5%" queries straightforward (filter `pagerank > 0.05/total_entities × constant`).

### 2.2 Sampled betweenness

Exact betweenness centrality (Brandes, 2001) is O(n·m), which at 10k entities and 30k edges is ~3×10⁸ operations — too slow.

We use **Riondato-Kornaropoulos sampling** (KDD 2014): pick k random vertex pairs, run BFS from each source, compute the contribution to betweenness from those paths only. With k = O(log(1/δ) / ε²) for ε-tolerance with confidence 1-δ. For ε = 0.01, δ = 0.05, k ≈ 50000 — but we don't need that tight a bound.

**We commit to k = 1000 sample pairs** as a practical default. Empirically gives ranking accuracy within ~5% on graphs up to 10k vertices. Implementation: igraph's `betweenness(cutoff=...)` with sampling enabled, or hand-rolled if igraph's sampling story is incomplete.

Output is normalised to [0, 1] by dividing by the maximum possible betweenness for a graph of n vertices: (n-1)(n-2)/2. Stored in `entity_topology.betweenness_sampled` (column name acknowledges the approximation).

### 2.3 Per-component vs global

PageRank: runs whole-graph. Damping handles disconnected components naturally — a vertex's PageRank is computed considering both within-component random walks and the teleport probability.

Betweenness: shortest paths exist only within components. Sampled betweenness produces meaningful values only for vertices in components of size ≥ 3. Vertices in size-1 or size-2 components get betweenness_sampled = 0.

### 2.4 Sample size as a parameter

The k = 1000 default is exposed via env var `BETWEENNESS_SAMPLE_SIZE` for tuning. `topology_compute_runs.error_detail` (which we already track) records the sample size used for each compute, so changes are auditable.

For the very small graphs (frankenstein-10chunks at ~60 entities), exact betweenness is feasible — we add a fallback: if `n ≤ 200`, run exact; otherwise sample. This gives the best fidelity on small corpora without slowing down large ones.

### 2.5 What's NOT centrality

- Articulation point membership (`23.3`) — structural criticality, not importance
- Community participation coefficient (`23.4`) — boundary-ness within community structure, not graph-wide importance

These compose with centrality but are conceptually distinct. A vertex can be high-PageRank and not articulation; vice versa.

## 3. Implementation

### 3.1 Module location

`ml-services/app/topology.py`:

```python
def compute_pagerank(g: igraph.Graph, damping: float = 0.85) -> dict[str, float]:
    """Whole-graph PageRank. Sums to 1.0."""
    pr = g.pagerank(damping=damping, eps=1e-6)
    return {g.vs[i]['name']: float(pr[i]) for i in range(g.vcount())}

def compute_betweenness(g: igraph.Graph, sample_size: int = 1000) -> dict[str, float]:
    """
    Sampled betweenness via NetworkX (which has native pair sampling).
    Exact via igraph for small graphs.

    Cold-eyes review B3 fix: igraph's betweenness() does NOT accept a sample_size
    parameter. NetworkX's betweenness_centrality(k=...) implements Riondato-Kornaropoulos
    pair sampling natively.
    """
    n = g.vcount()
    max_bw = (n - 1) * (n - 2) / 2 if n >= 3 else 1.0

    if n <= 200:
        # Exact via igraph
        bw = g.betweenness(directed=False)
    else:
        # Sampled via NetworkX (one-shot conversion)
        import networkx as nx
        nx_g = g.to_networkx()
        bw_dict = nx.betweenness_centrality(
            nx_g.to_undirected(),
            k=sample_size,
            normalized=True,
            seed=42,  # deterministic
        )
        # NetworkX returns {node: value}; map back to igraph index order
        bw = [bw_dict.get(g.vs[i]['name'], 0.0) for i in range(n)]

    return {
        g.vs[i]['name']: (float(bw[i]) / max_bw if (n > 200 or max_bw == 0) else float(bw[i]))
        for i in range(n)
    }
```

NetworkX's `k` parameter samples source vertices and runs SSSP from each — equivalent to Riondato-Kornaropoulos pair sampling for the per-vertex betweenness estimate. Already-normalised when `normalized=True`. The igraph branch normalises manually.

This requires `networkx` in `ml-services/requirements.txt` alongside `python-igraph` — both already in scope per master `23` §2.5.

### 3.2 Write-back

Standard upsert per `23.1` §3.2:

```sql
UPDATE entity_topology

```

### 3.3 Read patterns

- `SELECT entity_id FROM entity_topology ORDER BY pagerank DESC LIMIT 10` — top protagonists. Uses index `idx_entity_topology_pagerank`.
- `SELECT entity_id FROM entity_topology ORDER BY betweenness_sampled DESC LIMIT 10` — top bridges. Uses index `idx_entity_topology_betweenness`.
- `SELECT entity_id, pagerank, betweenness_sampled, participation_coef FROM entity_topology WHERE pagerank > X AND participation_coef > Y` — connector hubs.

### 3.4 Reasoning agent integration (boost, not replace)

Per master §6.5 + cold-eyes review W4: the reasoning agent currently picks targets by `last_reasoned_at` cooldown. This phase adds a **boost**, not a replacement. Concretely:

- The agent's `get_reasoning_targets` MCP tool (in `causal-agent.ts`) returns entities ordered by:
  1. `last_reasoned_at` IS NULL or older than cooldown threshold (primary filter — keeps the freshness invariant)
  2. Within the eligible set, ordered by `pagerank DESC NULLS LAST` (secondary — among eligible targets, prefer the structurally important; entities with NULL pagerank — fresh ingest before topology compute — sort to the end and are visited only when all populated entities are exhausted within their cooldown). Cold-eyes review W4 explicit ordering.

Without the boost, eligible targets are returned in random order. With the boost, the agent visits high-PageRank entities first within each cooldown cycle. After a full cycle, every entity has been visited; high-PR entities are visited more often per unit time but never to the exclusion of low-PR ones.

This contract changes the tool's SQL but not its interface. The reasoning agent prompt does not need to know about centrality — the boost is transparent.

### 3.5 No new endpoint

Standard read patterns via existing `/api/entities/:id` (extended to include topology columns) and `/api/components/:id`. A "top-k by PageRank" endpoint can be added to viz if needed, but it's not load-bearing for Phase 2.

## 4. Verification

### 4.1 Manual checks

- After `topology/compute` on an empty graph: no rows
- After compute on a graph with a known structure (star, line, etc.): PageRank and betweenness values match analytical expectations
- Top-10 by PageRank on `synthetic-10k`: values are concentrated in cluster modes (Gaussian centres are typically over-connected by design)
- Top-10 by betweenness on a graph with one bridge: the bridge endpoints rank highest

### 4.2 Automated tests

Test file `platform/src/test/harness/topology-centrality.test.ts`.

**PageRank:**
- **Empty graph:** no rows.
- **Single entity:** pagerank=1.0 (it's the only vertex; sum = 1).
- **Two disconnected entities:** each pagerank=0.5.
- **Star (1 hub, 4 leaves):** hub has highest PageRank; all leaves have equal lower values.
- **Triangle:** all three have equal PageRank=0.333.
- **Sum invariant:** `SUM(pagerank) FROM entity_topology` ≈ 1.0 within tolerance matching the convergence threshold (1e-6, per §2.1). Cold-eyes review W1: original 1e-9 tolerance was tighter than the algorithm's own convergence and would fail spuriously.
- **Stability across compute runs:** identical graph state produces identical PageRank values.

**Betweenness:**
- **Empty / single / two-entity:** betweenness=0 for all (no shortest paths involve them).
- **Path A-B-C-D:** B and C are on shortest paths; A and D are not. B and C have positive betweenness; A and D have 0.
- **Triangle:** every vertex on no shortest path between others (all paths are direct). All have betweenness 0.
- **Star:** the hub is on every shortest path between leaves; betweenness ~1.0. Leaves have 0.
- **Bridge graph (two triangles connected by one edge):** the bridge endpoints have high betweenness.
- **Exact vs sampled fallback:** for `n ≤ 200`, the test uses exact betweenness and asserts specific values; for larger graphs, asserts ranking only.
- **Sample size effect:** running with `BETWEENNESS_SAMPLE_SIZE=100` vs `=10000` produces similar rankings on `synthetic-10k` (top-100 overlap > 90%).

**Integration:**
- **Reasoning agent target boost:** seeded test verifies that, given two targets equally fresh by cooldown, the higher-PageRank one is returned first.
- **Snapshot benchmark:** `synthetic-10k` produces a PageRank distribution with ~20% of entities holding ~80% of mass (rough power-law), and a betweenness distribution that is heavily right-skewed (most entities have low betweenness, a few dominate).

## 5. Benchmark

### 5.1 Acceptance thresholds

| Graph size | PageRank target | Betweenness target | Combined hard cap |
|---|---|---|---|
| 100 entities | < 10 ms | < 10 ms (exact) | 50 ms |
| 1 000 entities | < 50 ms | < 1 500 ms (sampled k=1000 via NetworkX) | 3 000 ms |
| 10 000 entities | < 200 ms | < 8 000 ms (sampled k=1000 via NetworkX) | 15 000 ms |

Targets revised per cold-eyes review W8 (consequent to B3 fix). NetworkX `betweenness_centrality(k=1000)` on 10k vertices ~30k edges is roughly 5–10s in CPython; the 3s target assumed a non-existent igraph sample API. Master `23` §5.1 end-to-end budget (12s target / 30s cap) accommodates this.

Centrality is the heaviest of the five Phase 2 features. Targets reflect that.

### 5.3 What we measure over time

- **PageRank distribution shape** — should be roughly power-law (a few high-importance, many low). Sudden flattening means structure was lost; sudden concentration means a hub formed.
- **Top-10 stability across regenerations** — for LLM snapshots, the top-10 should be stable (the same protagonists appear). Drift is a signal worth investigating.
- **Betweenness sample-size sensitivity** — periodic offline experiment: run with k ∈ {100, 500, 1000, 5000, 10000} on synthetic-10k. If top-100 betweenness ranking is stable at k=1000 but unstable at k=100, the default is well-chosen. Recorded but not in CI.

## 6. Edge cases

| Case | Expected behaviour |
|---|---|
| Empty graph | No rows. |
| Single entity | pagerank=1.0; betweenness=0. |
| Two disconnected entities | Each pagerank=0.5; betweenness=0. |
| Disconnected components | PageRank still sums to 1 globally (damping handles it); betweenness is 0 for entities in components of size < 3. |
| Star (1 hub, N leaves) | Hub PageRank dominates; leaves equal lower; hub betweenness ~1.0; leaves 0. |
| Cycle (3-cycle, 4-cycle, ...) | All vertices have equal PageRank; betweenness varies (in a cycle, no vertex is on more shortest paths than others — all 0). |
| Self-referential fact | Excluded from graph; doesn't add to PageRank. |
| Expired fact | Excluded; centrality reflects active edges only. |
| same_as link | Counts as edge, contributing to both centralities. |
| Sample size 0 | Betweenness computation refused; raises clear error. |
| Sample size > number of pairs | Falls back to exact. |
| Cascade-delete | ON DELETE CASCADE removes row; recomputed next cycle. |
| Concurrent compute | Per `23` §8.1, short-circuits. |
| Floating-point drift | PageRank sum invariant tolerates 1e-9. Larger drift signals an algorithm regression. |
| Very high-degree single hub | Leiden may absorb its leaves into one community; centrality remains valid (hub PageRank dominates). |

### 7.2 Evolution signals

- PageRank distribution flattens or concentrates abnormally on regen — extraction or reconciliation behaviour change
- Top-10 betweenness stability < 90% across two consecutive regens of the same LLM snapshot — sample size may be too low
- Real-world ingest reveals a betweenness pattern not covered by fixtures — extend
- Reasoning agent boost integration regression — the agent visits high-PR entities at the wrong frequency
