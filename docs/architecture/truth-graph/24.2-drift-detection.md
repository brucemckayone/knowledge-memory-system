## 1. Purpose

**Question it answers:** Has an entity's meaning-space position shifted significantly since we last clustered it?

This is the only capability on the cluster-bridging menu that addresses identity transition as a **temporal phenomenon**. All other features are graph-snapshot-time analyses; drift watches *change over time*. The canonical case from `06-graph-meta-layer.md` line 209 — an entity introduced in one narrative voice and later referred to in another — produces drift in the entity's centroid that this feature detects.

Concrete operational use:

1. **Trigger reconciliation on drifted entities specifically.** Without drift detection, reconciliation runs on a schedule and looks at all candidate pairs. With drift, we can short-circuit: when an entity drifts, immediately invoke reconciliation_agent scoped to that entity. This focuses LLM compute on the cases most likely to need it.

2. **Phase 4's cross-cluster generator candidate signal.** An entity drifting from HDBSCAN cluster A toward cluster B is a hint that it might be co-referent with entities currently in B. Drift events feed Phase 4's candidate ranker.

3. **Audit and explainability.** When the reconciliation_agent later creates a `same_as` link, the drift event provides a "why now" answer: "entity X drifted at time T; we investigated; same_as link created."

## 2. Design

### 2.1 Algorithm: ADWIN

ADWIN (Adaptive Windowing, Bifet & Gavaldà, SDM 2007) is a streaming change-point detector with PAC bounds. For our use:

- Each entity has a per-entity ADWIN window of recent cosine similarities between live `entity_meta.centroid` and `entity_clusters.centroid_snapshot`
- New similarity observations are appended on each `semantic-clustering/compute` run
- ADWIN's internal logic detects when the window's distribution shifts beyond a confidence threshold; when it does, the window is split and a drift event is emitted

The math is O(log n) per update where n is the number of observations for that entity. State across runs lives in a side table (per-entity ADWIN state pickled as bytes) so cold restarts don't re-warm.

Why not simpler approaches:
- A fixed similarity threshold ("drift if cosine < 0.8") doesn't adapt to per-entity baseline noise — a normally-stable entity becomes interesting at a smaller magnitude than a normally-noisy one
- A sliding-window mean comparison requires picking a window size; ADWIN adapts the window automatically
- Bayesian online change-point detection (BOCPD) is more principled but more parameters; ADWIN is the established lightweight option

### 2.2 What "drift" means concretely

For each entity at each compute time t:

1. Compute `live_centroid_t` = current `entity_meta.centroid`
2. Read `snapshot_t-1` = `entity_clusters.centroid_snapshot` from previous clustering
3. Compute `similarity = cosine(live_centroid_t, snapshot_t-1)`
4. Compute `magnitude = max(0.0, min(1.0, 1 - similarity))` — clamped to `[0, 1]` (cold-eyes review W2). Cosine technically returns values in `[-1, 1]`; for nomic-embed-text (normalised, generally non-negative) the raw `1 - cosine` lives in `[0, 1]` in practice, but explicit clamping ensures ADWIN's PAC bounds at `δ=0.002` (calibrated for the unit interval) remain valid even if a future embedding model produces negative cosines
5. Append `magnitude` to the entity's ADWIN window
6. ADWIN checks for distribution shift in the window. If shift detected: emit drift event with `target_cluster_id` set to the nearest cluster centroid to `live_centroid_t` (computed by averaging `entity_clusters.centroid_snapshot` per cluster_id and finding the minimum cosine distance)

The first time an entity is observed (no prior snapshot), ADWIN window initialised. No drift event emitted.

### 2.3 Action thresholds

A drift event is emitted whenever ADWIN signals. Not every drift event triggers reconciliation — that would over-fire on small drifts. Two thresholds:

- **Detection threshold:** ADWIN's internal confidence (default δ=0.002). Below this, no event emitted at all.
- **Action threshold:** drift_magnitude > `DRIFT_ACTION_THRESHOLD` (default 0.3 — meaning cosine similarity dropped below 0.7). Above this, reconciliation_agent is invoked.

Drift events below the action threshold are still recorded (with `triggered_action='logged_only'`) for audit.

### 2.4 ADWIN state persistence

A small side table holds per-entity ADWIN state:

```sql
CREATE TABLE public.entity_drift_state (
  entity_id          UUID PRIMARY KEY REFERENCES public.entities(id) ON DELETE CASCADE,
  adwin_state_blob   BYTEA NOT NULL,
  observation_count  INTEGER NOT NULL DEFAULT 0,
  last_cluster_id    INTEGER,                       -- entity's cluster at last update; reset trigger (cold-eyes review B2)
  river_version      VARCHAR(20) NOT NULL,          -- river package version that produced the blob (cold-eyes review W3)
  last_updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

The blob is the pickled ADWIN object from `river`. Bytes only; not human-inspectable.

**Reset triggers:**
- HDBSCAN reassigns the entity (`current_cluster_id != last_cluster_id`) — the snapshot baseline changed, so the window resets. Detection: compare incoming `entity_clusters.cluster_id` to `last_cluster_id`.
- Pickle round-trip fails (corrupted bytes, river version mismatch on `river_version != current river.__version__`) — reset state, log warning, treat as fresh.

**river version pinning (cold-eyes review B3):** `ml-services/requirements.txt` pins `river>=0.21,<1.0`. Verified API surface for that range:
- Constructor: `river.drift.ADWIN(delta=0.002)`
- Update: `detector.update(value)` — single value per call
- Check: `detector.drift_detected` — property (not method); access via attribute, not method call

A bead-acceptance smoke test imports the library and exercises all three calls. If it fails, the bead does not close.

**Bulk-load pattern (cold-eyes review W4):** the per-entity pickle round-trip costs ~1-3ms each via CPython; at 10k entities that's 10-30s of pure pickle overhead and blows the §5 latency budget. The compute routine MUST: (a) load all states once at start (`SELECT entity_id, adwin_state_blob FROM entity_drift_state`); (b) unpickle into an in-memory `dict[entity_id, ADWIN]`; (c) mutate state objects in-process while iterating entities; (d) bulk `INSERT ... ON CONFLICT DO UPDATE` once at end. No per-entity pickle round-trip during the loop.

### 2.5 Integration with reconciliation_agent (cold-eyes review B1)

The existing `reconciliation_agent.py` Pydantic `ReconciliationRequest` rejects unknown kwargs and the existing prompt template bails when `candidates` is empty. Extending the existing endpoint isn't viable. Instead, ship a **sibling endpoint** with its own request model and prompt template:

```python
# ml-services/app/reconciliation_agent.py — new sibling endpoint

class ReconciliationDriftRequest(BaseModel):
    entity_id: str
    drift_magnitude: float
    centroid_snapshot: list[float]    # the prior centroid
    centroid_current: list[float]     # the drifted centroid
    source_cluster_id: int | None
    target_cluster_id: int | None
    mcp_config_path: str

class ReconciliationDriftResponse(BaseModel):
    result: str

RECONCILIATION_DRIFT_SYSTEM_PROMPT = """You are a drift-investigation agent. ... (separate prompt focused on single-entity investigation: "is this still one entity, or two?")"""

@router.post("/reconciliation-agent/drift", response_model=ReconciliationDriftResponse)
async def reconciliation_drift_agent(request: ReconciliationDriftRequest):
    ...
```

The platform-side wrapper (in `causal-agent.ts`):

```typescript
// Illustrative — the actual sidecar implementation is Python; this is the platform caller
const event = await emitDriftEvent(entityId, magnitude, sourceClusterId, targetClusterId);
try {
  const result = await invokeReconciliationDriftAgent({
    entity_id: entityId,
    drift_magnitude: magnitude,
    centroid_snapshot: snapshot,
    centroid_current: current,
    source_cluster_id: sourceClusterId,
    target_cluster_id: targetClusterId,
  });
  await markDriftActionTaken(event.id, 'reconciliation_invoked', result.run_id);
} catch (err) {
  await markDriftActionTaken(event.id, 'reconciliation_failed', null, err.message);
}
```

Why a sibling endpoint instead of extending the existing one:
- `ReconciliationRequest` is a Pydantic model with strict field validation; adding `drift_focus` would break the existing API
- The existing prompt template bails on empty candidates (line 162-171 of `reconciliation_agent.py`)
- The investigative pattern is fundamentally different — single entity vs candidate-pair iteration
- Cleaner separation: the existing agent stays focused on candidate-pair work; the sibling owns drift investigation

This is the inverse of the existing reconciliation pattern. For drift-driven invocation, the agent investigates a single entity and decides whether action is warranted.

### 2.6 Out of scope

- **Predictive drift** — anticipating drift before ADWIN signals, via centroid-trajectory regression. ADWIN is reactive only.
- **Multi-entity drift correlation** — detecting that *several* entities drifted in correlated ways (suggesting the corpus shifted, not individual identities). Future analysis.
- **Drift in same_as link state** — tracking when a same_as link's two endpoints drift apart. Future.
- **Backfill drift events from pre-Phase-3 history** — we don't have prior centroid snapshots, so we can't compute past drift. Drift detection starts at first compute.

## 3. Implementation

### 3.1 Module location

`ml-services/app/semantic_clustering.py` — `detect_drift()` function inside the same module as HDBSCAN:

```python
import river.drift
import pickle

def detect_drift(
    entity_id: str,
    live_centroid: np.ndarray,
    snapshot_centroid: np.ndarray,
    state_blob: bytes | None,
) -> DriftResult:
    """
    Update per-entity ADWIN state and check for drift.
    
    Returns: DriftResult(drift_detected, magnitude, new_state_blob).
    """
    similarity = cosine(live_centroid, snapshot_centroid)
    magnitude = 1.0 - similarity
    
    detector = pickle.loads(state_blob) if state_blob else river.drift.ADWIN(delta=0.002)
    detector.update(magnitude)
    
    return DriftResult(
        drift_detected=detector.drift_detected,
        magnitude=magnitude,
        new_state_blob=pickle.dumps(detector),
    )
```

Called once per entity per compute run, after HDBSCAN.

### 3.2 Write-back

For each drift event detected:

```sql
INSERT INTO entity_drift_events (
  entity_id, drift_magnitude, centroid_snapshot, centroid_current, triggered_action
) VALUES ($1, $2, $3, $4, $5);
```

For each entity's updated state:

```sql
INSERT INTO entity_drift_state (entity_id, adwin_state_blob, observation_count, last_updated_at)
VALUES ($1, $2, COALESCE((SELECT observation_count FROM entity_drift_state WHERE entity_id=$1), 0) + 1, NOW())
ON CONFLICT (entity_id) DO UPDATE SET
  adwin_state_blob = $2,
  observation_count = entity_drift_state.observation_count + 1,
  last_updated_at = NOW();
```

### 3.3 Read patterns

- `SELECT * FROM entity_drift_events WHERE entity_id = $1 ORDER BY detected_at DESC LIMIT 10` — recent drift history for an entity
- `SELECT * FROM entity_drift_events WHERE detected_at > NOW() - INTERVAL '7 days' AND triggered_action = 'reconciliation_invoked'` — recent action-triggering drift events
- `SELECT entity_id, COUNT(*) FROM entity_drift_events WHERE detected_at > NOW() - INTERVAL '30 days' GROUP BY entity_id ORDER BY COUNT(*) DESC LIMIT 20` — most-drifting entities (suspicious; multiple drifts may signal an over-merged or under-merged identity)

## 4. Verification

### 4.1 Manual checks

- After first `semantic-clustering/compute` on a fresh DB: no drift events (no prior snapshots)
- After second compute with no graph changes: no drift events (centroid unchanged ↔ snapshot)
- After artificially perturbing an entity's `entity_meta.centroid` (manual UPDATE) and recomputing: that entity has a drift event with `drift_magnitude > 0`
- ADWIN state is persisted: a third compute uses the existing window rather than starting fresh

### 4.2 Automated tests

Test file `platform/src/test/harness/drift-detection.snapshot.test.ts` (snapshot-using suite, serial).

- **First-time clustering:** no drift events. Every entity has fresh ADWIN state.
- **No-change recompute:** no drift events.
- **Single entity drifts:** simulate by updating `entity_meta.centroid` for one entity to a vector cosine-distant from its snapshot; recompute; one drift event emitted.
- **Drift below action threshold:** small perturbation (cosine 0.95); event emitted with `triggered_action='logged_only'`; no reconciliation invoked.
- **Drift above action threshold:** large perturbation (cosine 0.6); event emitted with `triggered_action='reconciliation_invoked'` (or `reconciliation_failed` if mocked agent fails).
- **Multiple drifts on same entity over time:** entity drifts twice across two computes; two events recorded.
- **ADWIN state persists:** state_blob round-trips through pickle correctly. After 10 computes with stable centroid, state shows 10 observations.
- **State reset on cluster reassignment:** if HDBSCAN puts the entity in a different cluster, the snapshot baseline changes; ADWIN state for the entity is reset.
- **Cascade-delete:** deleting an entity removes drift state and events.
- **Reconciliation agent invocation:** mocked agent receives the `drift_focus` payload correctly; the event's `reconciliation_run_id` is populated on success.
- **Bridge-pair simulation:** synthetic-10k bridge pairs are placed in different clusters per `28` §3.3 step 6. Their centroids do not drift between consecutive computes (each is stable in its own cluster). Drift detection correctly emits zero events on this stable case.

## 5. Benchmark

### 5.1 Acceptance thresholds

| Operation | Target | Hard cap |
|---|---|---|
| Per-entity drift check (in-memory) | < 1 ms | 5 ms |
| Pickle/unpickle ADWIN state | < 1 ms | 10 ms |
| **Full drift pass on 10k entities** | **< 1 s** | **5 s** |
| Reconciliation agent invocation overhead per drift event | < 100 ms (queueing only) | 500 ms |

Drift detection itself is cheap. The cost is in the resulting reconciliation_agent invocations, which are bounded by the number of action-threshold-exceeding events per cycle.

### 5.2 Baseline reports

Under `platform/src/test/data/phase3-clustering/benchmark-reports/drift/`:

- `synthetic-1k-drift.json` — no perturbations, expected 0 events
- `synthetic-1k-perturbed-drift.json` — 50 entities perturbed; expected 50 events
- `synthetic-10k-drift.json` — no perturbations, expected 0 events
- `synthetic-10k-perturbed-drift.json` — 100 entities perturbed; expected 100 events

Each: `{snapshot_name, total_entities, entities_perturbed, drift_events_emitted, reconciliation_invocations, false_positive_rate (events on unperturbed), elapsed_ms}`.

### 5.3 What we measure over time

- **False positive rate** — drift events on stable centroids. Should be < 1% under default ADWIN δ=0.002. If higher, lower δ.
- **Reconciliation invocation rate** — how often drift triggers an agent call. Bounded above by the action threshold's strictness. Tunable.
- **Bridge-pair stability** — synthetic-10k bridge pairs should NOT drift across computes (each is stable in its own cluster). If they do, the synthetic generator is producing noise centroids.

## 6. Edge cases

| Case | Expected behaviour |
|---|---|
| Entity with no prior snapshot | ADWIN initialised; no drift event possible. |
| Entity whose centroid hasn't changed | similarity ≈ 1.0; magnitude ≈ 0; ADWIN sees no shift; no event. |
| Entity reassigned to a different HDBSCAN cluster between computes | ADWIN state reset; new baseline. No drift event for the reassignment itself (the snapshot changes is the cause, not effect). |
| Entity assigned to noise (-1) | Drift detection still runs; comparison against the noise-cluster snapshot (which is just the entity's own centroid at that compute). Effectively no drift unless the entity moves significantly. |
| Reconciliation agent invocation fails | `triggered_action='reconciliation_failed'`; event preserved for retry; the drift state is not reset (next compute will re-evaluate). |
| Cascade-delete | Drift state and events removed. |
| ADWIN state corruption (malformed bytes) | Wrapped in try/catch; corrupted state reset to fresh; warning logged. |
| Cosine of zero vector | Mathematically undefined. Wrap with safety: if either vector has near-zero norm, skip drift check for this compute, log warning. |
| Concurrent compute | Rejected via status pattern. |
| `entity_meta.centroid` is now NULL (memories all expired) | similarity undefined; skip drift check for this compute. |

### 7.2 Evolution signals

- False positive rate > 1% on stable corpora — ADWIN δ needs tuning
- Reconciliation invocation rate trends upward over time without graph growth — drift threshold may be too low
- A real corpus repeatedly fires drift on the same entity without producing reconciliation outcomes — the entity is genuinely ambiguous; flag for manual review
- Bridge-pair stability test fails — synthetic generator's centroid variance is too high
