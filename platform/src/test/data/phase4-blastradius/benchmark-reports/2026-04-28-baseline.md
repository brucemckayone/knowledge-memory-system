## Findings

**All correctness assertions pass.** The 9-rule severity table, hypothetical zero-mutation invariant, cycle protection, citation correctness, and pattern-impact forward compat all behave per spec.

**Performance is correct but slower than the spec target on this workstation.** The recursive CTE (forward+backward 2-hop) terminates correctly on every fixture, but realistic-500-entity at depth=3 measured ~6s in the test wall clock vs the spec's <500ms target. The internal `analyzeImpact` measurement (between two `Date.now()` calls inside the test) was ~1s — the rest is fixture load + PG round-trips + vitest overhead. The spec's <500ms target was set against an unspecified machine; on this Docker-on-Windows setup the round-trips dominate.

The bidirectional CTE was tightened during C5: an earlier draft included "alternate cause / alternate effect" sibling-edge hops that produced a quadratic fan-out on hub events (250k row-pairs at depth 2 on the fan-out fixture, blowing past the 30s vitest timeout). The current 2-hop pattern (forward: `next.cause = chain.effect`; backward: `next.effect = chain.cause`) matches the existing `traceCauses` / `projectTrajectory` shape and is what the spec section "Transitive Chains" actually shows.

The ZERO-mutation contract under `hypothetical='expire'` is verified twice: once inline (facts.expired_at, invalid_at, causal_edges.expired_at, fact_history) and once via the assertion-runner against the 500-edge fan-out fixture.

## Next Iteration

- **Re-measure on Linux CI** — the Docker-on-Windows round-trip cost is a known factor. The spec's <500ms target should be re-checked against a Linux runner; if it still misses there, investigate query plan (hash join vs nested loop on the `edge_source_refs` lookup).
- **Level-3 fixture (`misra-chapter-impact.sql`)** — graduation criterion for `klv.4`. Real MISRA-derived dependencies validate severity scoring against a domain story rather than synthetic topology.
- **Investigate retroactive cycle protection on `traceCauses` / `projectTrajectory`** — filed as `nmemo-8vq.1`. Phase 4's CTE owns its own protection; the existing functions don't.
- **Adversarial: severity rule gaming** — build a graph where every dependent scores critical, assert the summary tally accurately reflects that without capping. Out of scope for this baseline; defer to klv.4.
- **Hypothetical-mode consistency** — currently only `expire` re-scores citations to critical. `invalidate` and `weaken` flow through the API but don't yet alter the rule table. Spec doesn't require it; flag for klv.4 design discussion.
