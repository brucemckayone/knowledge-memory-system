## Findings

**All Level 1 targets met.** Each of the four SQL heuristics:

1. `detectOpposingObjects` — flags non-exclusive opposing pairs, suppresses exclusive predicates, suppresses temporally-windowed pairs.
2. `detectExpiredButCited` — flags active edges citing expired facts, severity tier honoured (corroboration_count=1 → high).
3. `detectCyclicCausal` — flags A↔B with no temporal_span on either, suppresses cycles where both edges have a span.
4. `detectTemporalImpossible` — flags inverted-time edges with severity=high.

The orchestrator (`detectContradictions`) runs all four in parallel and returns aggregate counts. Re-running is idempotent because the partial unique index `idx_contradictions_unique_active` covers all four type patterns via COALESCE-with-zero-UUID-sentinel (closes the spec deviation #2 from the implementation plan: the spec only defined dedup for opposing/expired_but_cited; we extended to cover cyclic/temporal too).

Resolution dispatcher exercises every one of eight `resolution_type` branches:
- `expire_a / expire_b / expire_both` (chains into `expireFact` → audit + cascade fire automatically)
- `invalidate_a / invalidate_b` (chains into `invalidateFact`)
- `reconcile / both_valid / dismissed` (no fact mutation; closing UPDATE only)

End-to-end flow verified at four layers:
1. Service functions (direct call) — 12 tests
2. MCP tool dispatch via `handleToolCall` — 3 tests
3. HTTP endpoints via `app.request()` — 5 tests
4. Pipeline auto-trigger — wired into `pipeline.ts` decay counter; reasoning agent prompt block describes the patrol-time triage flow

## Performance highlights

The flood case (100 subjects × 2 facts each = 200 facts, 100 expected contradictions) detects in ~14ms — three orders of magnitude under the 2s budget. The bottleneck at this scale is the per-row `format()` call inside the SELECT; the JOIN itself is O(N²) over the candidate pair set but bounded by the partial unique index hit.

## Coverage gaps (graduation candidates for v1.1)

These are not failures — they're scenarios that the v1.0 fixtures don't yet cover. Each graduates the data set when added.

- **Multi-source severity tiers for `expired_but_cited`** — current fixture only tests corroboration_count=1 (severity=high). Add `expired-but-cited-corroborated.sql` with corroboration_count=3 to verify the 'medium'/'low' fallthroughs.
- **3-node cycles for `cyclic_causal`** — current heuristic catches 2-cycles only by design. 3+ cycles are reasoning-agent territory; document this boundary.
- **Microsecond-precision temporal inversions** — `temporal-edge-cases.sql` would test (a) cause.occurred_at == effect.occurred_at (must NOT flag — equality is allowed), (b) microsecond differences (must flag).
- **Concurrent flood resolution** — multiple agents resolving the same contradiction concurrently. The DB UPDATE WHERE id = … doesn't lock the row pre-update; the `if (resolvedAt)` check happens at SELECT time. Race window is small but exists. Add adversarial test.
- **`chain_conflict` agent path** — Level 2. Requires the reasoning agent to detect semantic conflicts during patrol; depends on agent-quality benchmarking framework.
